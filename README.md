# Nexus

A personal AI-coding setup (agents, skills, rules, hooks, and slash commands) for **Claude Code**, **Codex**, and **Gemini CLI**. Install it with whichever of those you use; none is required. See `INVENTORY.md` for a full list of what's included, and `CLAUDE.md` for the operating notes.

## Install

```bash
git clone https://github.com/SpurrellandCo/Nexus.git && cd Nexus && ./install.sh
```

This one command does everything:

1. **Installs Nexus at `~/.nexus`.** If you use Claude Code, it also links Nexus into `~/.claude`, the folder Claude Code reads its global config from: `~/.claude/skills` becomes a link to `~/.nexus/skills`, and likewise for agents, rules, commands, scripts, hooks, and `CLAUDE.md`. Your existing `~/.claude` stays where it is: `settings.json`, history, and projects are untouched. If you already have your own item where a link goes (say a `~/.claude/skills` folder), it's moved to `~/.claude/backups/` first, never deleted. Older Nexus installs, where the repo *was* `~/.claude`, are moved to `~/.nexus` automatically.
2. **Installs machine-level dependencies** (`uv`, the `graphify` CLI) via `bootstrap.sh`.
3. **Interactively prompts you for any API keys/tokens still missing** — press Enter on any prompt to skip it if you don't need that integration; you can always fill it in later by re-running `./install.sh` or editing `settings.json` / `mcp-configs/mcp-servers.json` directly.
4. **Asks once which AI tools to set up.** It detects Claude Code, Codex, and Gemini CLI and suggests the ones you have. It also asks whether to run a nightly sync (default no) and whether that sync may push (default no). Answers are saved in `~/.nexus-local/config.json`, outside the repo. See [Your settings](#your-settings).
5. **Gives each chosen tool Nexus's skills, agents, and instructions** right away. See [How each tool gets Nexus](#how-each-tool-gets-nexus).

Safe to re-run any time — re-running only fills in keys that are still placeholders, keeps your saved preferences, and won't touch keys you've already set.

Requires `git`, `python3`, and `node` (the hooks and helper scripts are Node).

### New Machine Setup (manual, without `install.sh`)

If you'd rather do it by hand: clone this repo to `~/.nexus`, run `bash ~/.nexus/scripts/nexus-claude-links.sh` to link it into `~/.claude`, then run `bash bootstrap.sh` to install machine-level dependencies (`uv` + the `graphify` CLI). It prints the remaining manual step of copying `settings.example.json` / `mcp-configs/mcp-servers.example.json` to their real filenames and filling in API keys yourself, since secrets are intentionally excluded from this repo. Then run `node scripts/nexus-link.js` to share skills and agents with Codex and Gemini CLI (optional). Per-project tooling (Playwright screenshot setup, project npm deps) is not part of this script — it installs automatically the first time Claude works in a given project, per the policy in `CLAUDE.md`.

## How each tool gets Nexus

Nexus's skills, agents, and instructions are written once and given to every tool you choose. No tool is required or special, and you never copy anything by hand.

| | Claude Code | Codex | Gemini CLI |
|---|---|---|---|
| Skills | `~/.claude/skills` (a link to `~/.nexus/skills`) | `~/.agents/skills` (one link per skill) | `~/.agents/skills` (shared with Codex) |
| Agents | `~/.claude/agents` (a link) | `~/.codex/agents/<name>.toml` (generated) | `~/.gemini/agents/<name>.md` (generated) |
| Instructions | Nexus block in `~/.claude/CLAUDE.md` (imports the files below) | Nexus block in `~/.codex/AGENTS.md` | Nexus block in `~/.gemini/GEMINI.md` |

- **Instructions** come from `NEXUS.md` (shared by every tool), `adapters/<tool>/instructions.md` (notes for one tool), the coding standards in `rules/`, and your personal notes in `~/.nexus-local/instructions.md` (never committed). They sit inside a marked `BEGIN NEXUS … END NEXUS` block; anything you write outside the block is yours and is never touched.
- **Generated files** say `GENERATED by Nexus`; edit the Nexus original instead, since generated files are rewritten.
- **When it updates:** after every Claude Code turn, every 10 minutes in the background (a small launchd job, set up when you choose Codex or Gemini CLI), from `update.sh`, and from the nightly sync. Run it yourself any time: `node ~/.nexus/scripts/nexus-link.js`.
- **Your own skills, agents, and instructions are safe.** Nexus only changes the links, files, and blocks it created. Anything else is left alone and listed in the output, with one exception: `--replace-copies` backs up items that have the *same name* as a Nexus skill, agent, or instruction file (for example, an older copied import) and replaces them. `--retire-unrelated` also backs up everything else; you should only need it to clear out stale leftovers. Backups go to `~/.nexus/backups/`.
- **Skills made in Codex or Gemini:** after you've run `--replace-copies` once, a new skill folder created directly in `~/.agents/skills` is moved into Nexus and linked back, so every tool gets it. Folders that were already there are never moved.
- **Adding or removing a tool:** edit `"tools"` in `~/.nexus-local/config.json` (for example `["codex"]`). The next update removes only what Nexus had set up for a tool you dropped.

Skills and agents are checked for tool-specific wording (`node ~/.nexus/scripts/nexus-portability.js --all`), so they work in every tool. The conventions are in `rules/nexus/portable-authoring.md`.

## Your settings

Per-machine choices live in `~/.nexus-local/config.json`, outside the repo so they are never committed:

```json
{
  "tools": ["claude", "codex", "gemini"],
  "sync": { "enabled": false, "push": false }
}
```

- `tools`: which AI tools Nexus sets up (`claude`, `codex`, `gemini`). The installer detects what's installed and asks.
- `sync.enabled`: run the nightly sync (macOS launchd, 21:00). It commits changes to Nexus's own files (skills, agents, rules, scripts, and so on) to your local checkout. Tool caches and runtime files are never committed.
- `sync.push`: also push those commits to `origin`. **Only turn this on for your own repo or fork**, and remember that a public repo publishes whatever you push. With no config file, Nexus sets up every tool and never pushes.

After changing `sync.enabled`, re-run `./install.sh` to add or refresh the nightly schedule. Older configs with `"shareWith"` still work.

### Claude Code: custom endpoints and gateways

Nexus doesn't change Claude Code's transport settings. If Claude Code runs through an LLM gateway or a compatible custom endpoint, Nexus keeps working, because its hooks and skills run locally once the CLI has started.

Use Claude Code's own environment/configuration for transport selection, for example:

```bash
export ANTHROPIC_BASE_URL=https://your-gateway.example.com
export ANTHROPIC_AUTH_TOKEN=your-token
claude
```
