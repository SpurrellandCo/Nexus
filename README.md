# Nexus

A personal AI-coding setup (agents, skills, rules, hooks, and slash commands) built for Claude Code and shared automatically with **Codex** and **Gemini CLI** on the same machine. See `INVENTORY.md` for a full list of what's included, and `CLAUDE.md` for the operating notes.

## Install

```bash
git clone https://github.com/SpurrellandCo/Nexus.git && cd Nexus && ./install.sh
```

This one command does everything:

1. **Places the config at `~/.claude`** — the exact path Claude Code reads global config from. If you already have a `~/.claude` (common if you already use Claude Code), it's backed up first, never overwritten — and if that backup has a real `settings.json` / `mcp-servers.json` with your existing API keys, those are carried forward automatically so you don't lose them.
2. **Installs machine-level dependencies** (`uv`, the `graphify` CLI) via `bootstrap.sh`.
3. **Interactively prompts you for any API keys/tokens still missing** — press Enter on any prompt to skip it if you don't need that integration; you can always fill it in later by re-running `./install.sh` or editing `settings.json` / `mcp-configs/mcp-servers.json` directly.
4. **Asks three questions once** and saves the answers in `~/.nexus-local/config.json` (outside the repo): whether to share Nexus with Codex and Gemini CLI (default yes), whether to run a nightly sync (default no), and whether that sync may push (default no). See [Your settings](#your-settings) below.
5. **Shares skills and agents with Codex and Gemini CLI** right away, if you said yes. See [Using Nexus with Codex and Gemini CLI](#using-nexus-with-codex-and-gemini-cli).

Safe to re-run any time — re-running only fills in keys that are still placeholders, keeps your saved preferences, and won't touch keys you've already set.

Requires `git`, `python3`, and `node` (the hooks and helper scripts are Node).

### New Machine Setup (manual, without `install.sh`)

If you'd rather do it by hand: clone this repo directly to `~/.claude`, then run `bash bootstrap.sh` to install machine-level dependencies (`uv` + the `graphify` CLI). It prints the remaining manual step of copying `settings.example.json` / `mcp-configs/mcp-servers.example.json` to their real filenames and filling in API keys yourself, since secrets are intentionally excluded from this repo. Then run `node scripts/nexus-link.js` to share skills and agents with Codex and Gemini CLI (optional). Per-project tooling (Playwright screenshot setup, project npm deps) is not part of this script — it installs automatically the first time Claude works in a given project, per the policy in `CLAUDE.md`.

## Using Nexus with Codex and Gemini CLI

Nexus's skills and agents are written once and shared with every AI coding tool on the machine. You never copy them by hand.

- **Skills** are linked (symlinks, not copies) into `~/.agents/skills`, the folder both Codex and Gemini CLI read. Editing a skill in Nexus updates it everywhere.
- **Agents** are converted into each tool's format: `~/.codex/agents/<name>.toml` and `~/.gemini/agents/<name>.md`. Generated files say `GENERATED by Nexus` at the top; edit the Nexus original instead, since generated files are rewritten.
- **When it runs:** at install, after every Claude Code turn (a Stop hook), from `update.sh`, and from the nightly sync. You can run it yourself: `node ~/.claude/scripts/nexus-link.js`.
- **Your own skills and agents are safe.** Nexus only ever changes the links and files it created. Anything else in those folders is left alone and listed in the output, with one exception: `--replace-copies` backs up folders or agent files that have the *same name* as a Nexus skill or agent (for example, an older copied import) and replaces them with Nexus's version. `--retire-unrelated` also backs up everything else; you should only need it to clear out stale leftovers. Backups go to `~/.claude/backups/`.
- **Skills made in Codex or Gemini:** after you've run `--replace-copies` once, a new skill folder created directly in `~/.agents/skills` is moved into Nexus and linked back, so every tool gets it. Folders that were already there are never moved.
- **Opting out:** set `"shareWith"` in `~/.nexus-local/config.json` to `[]` (Claude Code only) or `["codex"]` / `["gemini"]`. The next run removes only what Nexus had shared.

New skills and agents are also checked for Claude-only wording as they're written (`scripts/hooks/portability-check.js`), so they work in every tool. The conventions are in `rules/nexus/portable-authoring.md`; run `node ~/.claude/scripts/nexus-portability.js --all` for a full report.

## Your settings

Per-machine preferences live in `~/.nexus-local/config.json`, outside the repo so they are never committed:

```json
{
  "shareWith": ["codex", "gemini"],
  "sync": { "enabled": false, "push": false }
}
```

- `shareWith`: which tools get Nexus skills and agents (`[]` for none).
- `sync.enabled`: run the nightly sync (macOS launchd, 21:00). It commits changes to Nexus's own files (skills, agents, rules, scripts, and so on) to your local checkout. Claude Code's caches and runtime files are never committed.
- `sync.push`: also push those commits to `origin`. **Only turn this on for your own repo or fork**, and remember that a public repo publishes whatever you push. With no config file, Nexus shares with Codex and Gemini and never pushes.

After changing `sync.enabled`, re-run `./install.sh` to add or refresh the nightly schedule.

### Plugin Manifest Gotchas

If you plan to edit `.claude-plugin/plugin.json`, be aware that the Claude plugin validator enforces several **undocumented but strict constraints** that can cause installs to fail with vague errors (for example, `agents: Invalid input`). In particular, component fields must be arrays, `agents` is not a supported manifest field and must not be included in plugin.json, and a `version` field is required for reliable validation and installation.

These constraints are not obvious from public examples and have caused repeated installation failures in the past. They are documented in detail in `.claude-plugin/PLUGIN_SCHEMA_NOTES.md`, which should be reviewed before making any changes to the plugin manifest.

### Custom Endpoints and Gateways

ECC does not override Claude Code transport settings. If Claude Code is configured to run through an official LLM gateway or a compatible custom endpoint, the plugin continues to work because hooks, skills, and any retained legacy command shims execute locally after the CLI starts successfully.

Use Claude Code's own environment/configuration for transport selection, for example:

```bash
export ANTHROPIC_BASE_URL=https://your-gateway.example.com
export ANTHROPIC_AUTH_TOKEN=your-token
claude
```
