# Working on the Nexus repo

Project instructions for any AI tool (or person) changing Nexus itself. The instructions Nexus gives every tool are in `NEXUS.md`; this file is only about maintaining the repo.

## Layout

| Path | What it is |
|---|---|
| `NEXUS.md` | Shared instructions for every tool (written into each tool's global instruction file by `scripts/nexus-link.js`) |
| `adapters/<tool>/instructions.md` | Notes for one tool only (claude, codex, gemini) |
| `skills/`, `agents/`, `commands/` | Shared skills, agents, slash commands |
| `rules/` | Coding standards; `rules/nexus/` is written into every tool's instructions, the rest are indexed |
| `scripts/` | Linker, installer helpers, hooks, and their tests |
| `INVENTORY.md` | Generated by `scripts/generate-inventory.js`; don't hand-edit |

## Conventions

- **Portable first:** anything shared must work in every tool. Tool-specific details go in `adapters/<tool>/` or under a "Tool-specific notes" heading. Check with `node scripts/nexus-portability.js --all`.
- **Public repo:** no secrets, personal details, or machine-specific paths. Per-machine state lives in `~/.nexus-local/`.
- **Tests:** `node --test scripts/tests/*.test.js` must pass. Write the test first for new behavior.
- **No regressions:** before and after a restructure, compare with `node scripts/nexus-baseline.js --compare <baseline.json>`.
- **Commits:** conventional format (`feat:`, `fix:`, `chore:` ...), one logical change per commit.
